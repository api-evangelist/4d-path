# 4D Path

> 4D Path, Inc. is a computational-pathology company in Newton, Massachusetts, founded in 2016.
> Its Q-plasia OncoReader (QPOR) platform applies statistical physics and cancer biology — not
> conventional image-classification AI — to digitized H&E-stained whole-slide biopsy and
> resection images, quantifying cell-cycle deregulation and tumor immune microenvironment
> dynamics to produce biomarker profiling, grading and therapy-response prediction without
> additional molecular assays (IHC, FISH, RNA-Seq, NGS). Its lead software-as-a-medical-device
> product, 4D Q-plasia OncoReader Breast, received FDA Breakthrough Device Designation in
> November 2020.

## Status

4D Path publishes **no public API**, no developer portal, no API reference, no SDK, no CLI and
no machine-readable contract. As of 2026-09-05, probes on `4dpath.com` for `/openapi.json`,
`/openapi.yaml`, `/swagger.json`, `/v1/openapi.json`, `/api-docs`, `/docs`, `/redoc`, `/api`,
`/graphql`, `/llms.txt`, `/apis.json`, `/apis.yml` and the full named `/.well-known/` list
(`security.txt`, `openid-configuration`, `oauth-authorization-server`,
`oauth-protected-resource`, `api-catalog`, `ai-plugin.json`, `apis.json`,
`aauth-resource.json`, `ucp.json`, `acp.json`, `agent-card.json`, `agent.json`) all returned
404. One API-shaped host resolves in DNS — `api.4dpath.com`, an Azure Web App — and it answers
Microsoft's stock "Azure Web App - Error 404" page for the site root and for every path
probed, so nothing is publicly routed there. No `docs.`, `developer.`, `portal.`, `app.` or
`platform.` subdomain resolves. No npm, PyPI or GitHub organization exists under the 4D Path
name. The QPOR reader reaches pathologists inside PathPresenter's ClinPx viewer, through
PathPresenter's own integration surface, rather than through a 4D Path API.
